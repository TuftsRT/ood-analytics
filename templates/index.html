            Errors and slow requests

            Server errors are HTTP 5xx responses; client errors are 4xx. Slow requests took longer than the threshold to answer. Requests that couldn't be tied to a signed-in user still count.

              Response times by area

              Static files, websockets, and traffic to running interactive apps aren't timed. Percentiles are to the nearest histogram bucket.

              Apache isn't logging response times yet, so slow page loads can't be measured. Add %D (microseconds) to the end of the access log format in /etc/ood/config/ood_portal.yml:

              logformat: '"%h %l %u %t \"%r\" %>s %b \"%{Referer}i\" \"%{User-Agent}i\" %D"'

              Then run /opt/ood/ood-portal-generator/sbin/update_ood_portal and restart Apache. The collector picks the times up from the next log lines on; error counts below work either way.

              Server errors (5xx)

              A 502 or 503 under an OnDemand app usually means that person's web server crashed or was restarting; under Interactive App Connections it usually means the app's session had ended. 504 is a timeout.

              Client errors (4xx)

              404s are often stale bookmarks or missing files; a run of 401 or 403 can point to sign-in or permission problems.
